# Error functions

Different types of error functions are useful in different positions of the system of optimal interactions between interface structures.


## Error function types

- Error functions that identify all possible core error structures of vector/network interactions like 'too many duplicate vectors' (implying that 'suboptimal/probably false'connections like 'everything is equal' are applied) or 'too many unused vectors' (implying that many irrelevant possibilities were generated, which is suboptimal) or 'combinations/structures of core error structures' which are identifiable as error structures

- Error functions that check for solution function errors like 'over-specificity' given an 'assumed set of optimization metrics of solution functions' (like 'generality is good' and 'only one function should be identified' and 'fitler out outliers')

- Error functions that check for errors in assumptions used to 'identify optimization metrics of solution functions'

- Error functions that check for 'errors of a solution function, across relevant graphs' like the 'solution function rarely occurs in relevant graphs, indicating that its improbable'.

- Error functions that check for 'aggregate/relevant error scores across multiple/relevant error types' like an 'average of variants of mean squared error'.


## Error function interactions

It is unlikely that all of these error functions should be integrated to generate one 'error score' for a possible solution function.

Rather it is likely that a 'system of optimal interactions between error functions' should be identified and applied to decide 'which metrics generated by which functions should be integrated in which structures'.
