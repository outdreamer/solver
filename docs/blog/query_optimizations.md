# Query Optimizations


## Relevant query intents

'Predicting an optimal query, to connect nodes in a graph' is the graph variant of the problem 'predicting an optimal connection function from a data set'.

'Predicting an average/representative function' is one intent in a set of possible variant intents involving 'predicting a connection function from a set of points/nodes'.

'Predicting a different structure from another structure' is the general variant of 'predicting a connection function from a set of points/nodes'.


## Optimal query structures

Example optimal query structures:
- queries that have predictable shapes like core/common shapes, while connecting maximal differences like opposite points or otherwise disconnected/isolated/independent points
- queries that trivially/uniquely/predictably/otherwise usefully connect maximally different nodes
- queries that are reusable/otherwise useful across maximally different graphs
- queries that are reusable/otherwise useful across maximally different intents, as in queries that implement multiple/otherwise useful intents (queries that connect multiple maximally different node pairs)
- queries that 'trivially/otherwise usefully' identify 'reusable/otherwise useful' emergent similarities/differences in the graph


## Query optimizations

Example query optimizations include:
- identify relevance structures in the graph like 'general connections in the graph'
- identify structures/spectrums like relevance/error/variable structures/spectrums to 'identify error directions to avoid'
- identify local functions that can identify local errors/relevance structures without general information
- optimize a query for a general relevant intent like 'identify similar structures'
- optimize a query for general interface variable optimization metrics like 'degree of volatility'
- identify the maximally different similarities that could possibly emerge from a set of input/generative/descriptive graph similarities (like similarities in variables that arent included in the graph definition) and identify local functions to check for those similarities

Optimal query structures like 'queries with core shapes (like spirals)' can be used to generate query optimizations like 'identify queries that will likely have core shapes when connecting any node set, by the fact that the query generates components of core structures locally'.


## Graph optimizations

Graph optimizations can optimize queries.

Example graph optimizations include:
- changes that make optimal query shapes more predictable or that make queries more trivial/otherwise useful
- changes that implement more relevance insights into the graph's structure (as in 'connecting additional nodes trivially/otherwise usefully')
- changes that make other relevant graphs more trivial/otherwise useful to identify/generate (like changes to apply a set of intersecting spectrums as axes of a graph, which identifies other sets of intersecting spectrums as possible graph variables, and identifies the graph of these graph variants as a relevant graph)
- changes that reduce a graph to a graph description or a point on a graph of graphs
