# Error graph structures

A graph of explicit problem structures like 'missing info' or 'extreme variable values' or 'complexity structures' can be useful to combine with other structures to identify/represent/generate problems.


## Defined error structures

Missing/extreme/imbalanced structures are defined core error structures.

Related structures of errors like 'missing info/connections' are error structures like 'gaps'.


## Conditional interface variable error structures

Complexity is often an error structure, where 'extremes of complexity' are defined as an error, though it varies and is conditional, so complexity can be neutral or a solution structure.


## Emergent error differences with structure

Interface structures like 'combinations/sequences/connections' can generate sufficient differences to generate an error, so these can emerge as error structures.


## Error structures in graphs

On their own, these structure types (variables like complexity, structures like missing structures or gaps) aren't necessarily error structures, but in combination with other information like solution metrics and relevant problem/solution structures, it becomes clear whether a structure is an error structure. If it is a 'gap between a problem/solution, which should be connected', then it's an error structure. Is the solution metric 'connectability by any path' rather than 'distance'? Then a gap between a problem/solution might not be an error structure.

A graph of 'cross-interface error/variable structures' like 'missing specificity' or 'extreme complexity' is a graph of problem/solution structures.

A graph of 'iterated interface differences' also likely generates enough differences to be a graph of both problem/solution structures.

Even a graph of only error types also has connections between those error types, and these connections are likely to overlap with solution structures, even if they're not represented otherwise on the graph.
