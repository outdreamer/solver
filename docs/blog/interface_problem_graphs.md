# Interface Problem Graphs

Interface graphs of a graph, like the 'limit graph' of a graph, are useful to identify, in order to identify useful graphs to apply in a 'combination/sequence/other structure'.

Interface problem/solution graphs are useful graph variants of a problem/solution connection graph which are useful to apply in a 'combination/sequence/other structure'.

Different problem/solution graphs are useful, based on interface variables like 'certainty' and related variables like 'specificity', 'probability', 'dependency', 'integration/interactivity', and 'validity'.


## Low certainty problem/solution graphs for unsolved problems with unidentified/new solutions

### Identify new paths of "solution functions/actions/steps" to "solution messages" for "unsolved problems"

This calls for a graph connecting 'error messages' (like an 'error code') with 'solution messages' (like a 'success message'), which is useful for queries like 'solve an unsolved problem, by identifying a new path to a solution message, connected by cause/following/similar/other connection types'.


### Identify probably similar nodes to a problem/solution

This calls for a graph connecting input unsolved problems with 'similar problem nodes', which is useful for queries like 'solve an unsolved problem, by identifying similar problems and paths leading to the solutions of similar problems, and similar solutions to the solutions of similar problems'.


## High-certainty problem/solution graphs for solved problems with identified solutions

### Identify specific problems/solutions associated with problem types

This calls for a graph connecting 'specific solutions/problems and problem/solution types', which is useful for queries like 'identify a solution by identifying the specific problem of an input problem, then identifying the problem type of the specific problem, then identifying the opposing solution type of the problem type, then identifying the specific solution of the solution type'.


### Identify opposing problems/solutions

This calls for a graph connecting 'opposing/following sections in documents' as relevant 'problem/solutions', which is useful for queries like 'identify a solution by identifying the opposing/following sections of a problem section in a document'.


## Predicting problems with dependency graphs of problem types

### Identify the next problems caused by a known problem and solutions to prevent the next problems

This calls for a graph connecting problem types or problems by causality and opposing solutions of caused problems, which is useful for queries like 'identify problems caused by this problem' and 'identify solutions to prevent problems caused by this problem'.


## Integrating problems/solutions

### Identify the integrated solution of a set of solutions

This calls for a graph connecting solutions into a merged/integrated solution, given the possible interactions of the solutions, which is useful for queries like 'identify the valid integration of input solutions (valid as in with no identified contradictions/other errors in the integrated solution, given the solution metrics of each integrated solution)'.


## Combinations/sequences of graphs

It's useful to apply some graphs in a combination/sequence/other structure.

For example, identifying the identified solution for a problem in the specific problem/solution graph, then identifying possible new solution paths in the 'probably similar problem/solution graph' in case the identified solution doesnt work, then identifying caused problems and solutions to prevent caused problems by the problem dependency graph, then integrating identified solution, possible new solutions, and solutions to caused problems in the solution integration graph to identify a solution that solves the problem and caused problems and doesnt have any contradictions/other invalidities - is a useful graph sequence to apply.
