# Relevant Graphs to Connect

Relevant graphs include 'similar graphs with enough differences to be useful to connect' and 'different graphs with possible similarities that are useful to identify', with varying relevance structures like 'general relevance' or 'relevant for a specific intent/optimization metric'.


## Relevant graphs

Identified relevant graphs like the 'similarity index graph' and the 'grid of intersecting interface spectrums' and the 'core intersecting spectrum graph' and the 'intersecting spectrum combination graph' are similar in that they all can apply 'intersections between interface spectrums', but they are different enough to be useful to connect. There is some uncertainty in 'how differently these graphs connect spectrums', so they are useful to connect to resolve that uncertainty.

Graphs can be generally relevant (like 'core relevant graphs like the similarity index graph') or specifically relevant (like 'relevant to a graph optimization intent, from a starting graph'), and can be relevant in other interface spectrums/structures.

It is useful to connect core relevant graphs which are 'generally relevant' and apply these connections as 'limits/filters/generators' of new relevant graphs.


## Relevant similar graphs

Relevant similar graphs have some similarity in common, like a common variable, and are different enough to be useful to connect, like having interface variable differences.

Example:
- 'graphs of optimizations', 'graphs of optimizations of optimizations', 'graph of optimizations of graphs' have 'optimization' in common and are also similar in the 'degree of interface structures applied', but are different enough to be useful to connect (there is enough uncertainty generated by these differences like 'iterations' that it is useful to identify the connections between these graphs, as opposed to being obviously connectible/certain)


## Relevant different graphs

Relevant different graphs are maximally different in some way like 'applying maximally different generative functions/graphs/variables', but have enough possible similarities to be useful to connect.

Example:
- 'graphs of interfaces of interfaces' and 'graphs of graphs of graphs' have primarily only an 'iteration' in common, and the difference between the iterated variable ('interfaces' and 'graphs') allows enough uncertainty that it is likely useful to connect these graphs (as in 'useful to connect maximally different structures')


## Connecting relevant graphs

It is useful to connect graphs by relevant intents, like 'generate optimal variants of a graph, for intents like "identify/generate new relevant graphs"'.

Connecting graphs by relevance structures like 'relevant intents' is generally optimal, and connecting graphs generally generates relevant graphs.

Applying a 'graph of graphs' or an 'intent similarity graph' are a useful set of starting graphs to connect relevant graphs.

'Applying changes to sets of starting graphs' to 'identify intersections/overlaps/connections/similarities between starting graphs' is a useful general intent to 'identify relevant graphs'.

Identifying 'optimal changes to apply to connect starting graphs' like 'optimal change types/directions/structures to apply' is a useful general intent as well.
