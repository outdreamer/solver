# Optimization Errors

Optimization errors are errors of solution structures, like errors that are caused by a solution. Avoiding optimization errors can identify/generate optimization algorithms with minimal errors.


## Optimization error structures

Optimization errors have the same structure as 'error structures', applied to solution structures.

- an over-prioritization error is an error of applying an overly simple priority, like one priority, to an extreme degree, as can occur when optimizing for only one metric.
- a missing optimization error is an error of failing to apply a general optimization metric like 'sufficient specificity for relevance' that should be applied across problems
- an opposing optimization error occurs when optimizing for an extreme on some optimization metric spectrum, which creates the opposite effect of actually optimizing for the other extreme on the same spectrum
- a cross-interface optimization error occurs when optimizing for an extreme on some optimization metric spectrum, which creates the different effect of actually optimizing for an extreme on a different spectrum, like a maximally different spectrum


## Different formats of optimization errors

Optimization errors have associated variants in different structures, like interfaces or graphs.

For example, graph 'over-prioritization' optimization errors occur when 'optimizing a graph for only one query', so that another query is less optimized for.


## Graphs with optimization errors

Examples of graphs associated with optimization errors:
- a graph associated with the optimization error 'over-prioritization' is the 'intersecting variable spectrum graph', where each direction is associated with one variable. A solution to this graph would be a graph of combinations of variables indicated by spectrums, so that each spectrum indicates an optimization for multiple variables simultaneously rather than only one at a time
- another graph associated with an optimization error of 'over-prioritization' like 'optimizing for only one query' is a graph with some 'similarity like adjacency' between a 'subset of nodes', rather than a solution graph which might be a 'graph with equidistance between all nodes' or a 'graph with subsets optimized for different similarity types'
- a graph with 'interface variable extremes in different directions' like the 'intersecting spectrum graph' has an optimization error of 'missing a general optimization metric like "sufficient specificity for relevance"' by excluding specific structures associated with different points on the spectrums, which is solved by including associated specific structures with each relevant point on the spectrums
- similarly, a graph with 'one intersection' like the default 'intersecting spectrum graph' is missing 'variants of intersections', which is solved by converting the graph into a 'grid of intersecting spectrums' or by 'graphing connections between points on one spectrum which implement/optimize/standardize/similarize/otherwise intersect with points on another spectrum' (points of 'high complexity' which are also points of 'high variation')


## Relevant graphs implementing optimization metrics

Relevant graphs like the 'intersecting spectrum graph' or the 'similarity index graph' are graphs which optimize for 'multiple optimization metrics' by integrating 'multiple maximal differences' like 'cross-interface structures' or otherwise implementing 'multiple optimization intents/metrics'. Relevant graphs can also be generated by applying other optimization structures than 'multiple optimization metrics'.


## Optimizing a graph

'Adding identified optimization structures to graphs, in an optimal sequence of optimization structures' is an implementation intent of general intents to 'optimize a graph'.

Similarly, 'identifying a relevant path between identified optimization errors to avoid those errors' is another implementation intent to 'optimize a graph'.
