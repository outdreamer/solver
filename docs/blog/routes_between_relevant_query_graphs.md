# Routing between relevant graphs of queries

Relevant graphs of queries that are useful to connect include:
- graphs of 'a query being run across relevant graphs', like graphs of the 'limits/assumptions of a query'
- graphs of 'queries of query graphs like graphs of limits/assumptions of a query'
- graphs of 'query variants across different graphs or in the same graph'
- graphs of 'optimal queries on a graph'
- graphs of 'relevant "directions of change/other interface structures" to apply changes to a query in'
- graphs of 'query optimizations'
- graphs of queries/workflows given 'possible/applied/otherwise relevant optimizations'

Identifying 'relevant routes between these query graphs' like 'when to stop processing a query on one graph and switch to another graph' and 'when to merge/otherwise change graphs to optimize for similar queries or query components' is useful to identify 'optimal queries of these query graphs'.

Relevant metrics of queries include 'complexity/variation/other interface variables'.

These metrics also apply to query graphs, so identifying 'limits/ratios/exponential changes/structures of relevant complexity' represented by a 'graph' or a 'query of a graph' or 'changes in a direction on a graph' is useful to identify 'when to start/stop iterating/changing/running queries on a graph'.

These metrics are useful to integrate across query graphs, like by identifying the 'relative complexity added by a graph, compared to a similar/opposing/abstract/otherwise relevant graph', to minimize 'irrelevant complexity' or 'mismatched variation' and otherwise optimize queries across graphs.
