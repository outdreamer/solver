# How to apply interface analysis using this repo


There are many coordinating intent sets with which to implement the structures in this repo to implement interface analysis.


## Example implementation steps

1. identify sets of structures (identify sets of graph intents, optimization intents, relevant graphs, interface variables, workflows, problem-solving structures, etc), in order to define these structures and their variants

2. identify rules of the optimal interactions of these structures (identify rules indicating how optimization intents interact optimally with graph intents)

3. identify implementations of these rules of optimal interactions

4. identify optimizations of implementations of these rules of optimal interactions

5. identify errors in optimizations of implementations of these rules of optimal interactions

6. identify solutions to errors in optimizations of implementations of these rules of optimal interactions

7. continue identifying errors/solutions until the same intents/variables/structures are re-used

8. when no new structures/variables/interfaces are identified/generated, that is a good stopping point to start running the script generated by the previous steps


## Patterns of implementation steps

You can see there are patterns in what constitutes legitimate implementation steps:
- there is a stopping point where the script is considered sufficiently optimal to be applied
- there are valid intent sequences like 'identify graphs, then optimize the graphs, then apply the graphs'
- there are multiple interfaces applied, specifically connecting regularly to the problem/solution interface
- each step results in outputs that can be applied as an input to the next step (the steps have an optimal sequence)
- each step involves a cross-interface structure, to connect the interfaces

These patterns can be applied as variables of implementation steps.


## Examples of LLM queries

LLM queries to use this repo include:
- identify different 'graphs of the optimization rules' in the solver repo, until a graph is identified that 'optimally generates new optimization rules', which 'dont contradict the existing rules or are more optimal than the existing rules', using the 'definition of optimality/relevance' from the solver repo
- generate interface structures of 'variables in this custom data set' according to the 'definition of interface structures' in the solver repo to 'enhance the data set, and identify useful variable interactions in the enhanced data set', until its 'trivial to solve for a custom intent related to the data set, like predicting this specific variable'
- 'generate relevant graphs' as defined in the solver repo and identify useful interactions/optimizations of or connections between those graphs, until a useful 'graph of relevant graphs' is generated by the graph connections/interactions that 'identifies new relevant graphs' or 'optimizes the interactions of the relevant graphs' or 'optimizes the relevant graphs'
- 'identify all useful variable interactions' in the solver repo and 'generate a relevant graph of these variable interactions' and apply that graph as a 'problem-solving workflow-filtering graph' or a 'general variable connection graph'
- 'identify the most optimal rules' in the solver repo and 'identify optimal usages of those rules' (like 'optimal rules that can be scaled/iterated indefinitely')
- 'applying the definition of relevance/optimality' in the solver repo, 'identify relevant/optimal structures' in the 'system representing by this data set/graph'
- 'applying the examples of relevant graphs' in the solver repo, 'identify relevant graphs that are required to solve this problem, in this system, represented by this data set/graph'
