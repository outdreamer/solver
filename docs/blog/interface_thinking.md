Interface thinking

I thought I'd write a blog about interface thinking, because I'm not seeing it happening from my previous explanations.

A normal simple thought uses common simple words as nodes in a neural network, like 'the cup is on the counter' or the 'function has a limit'. This applies 'simple 1-degree interface structures', like 'connections' or 'boundaries' or 'structures'. This is so simple as to be totally inaccurate and irrelevant, so I will call this type of thinking 'non-interface/irrelevant thinking', even though there is a slight, irrelevant overlap between this type of thinking and interface thinking. This type of non-interface, simple, 1-degree interface structure thinking will often generate errors like 'simple structural similarities, which fail to identify relevance/meaning'. Picture a graph of intersecting vectors - what is most relevant about this graph? Is it the simple vectors themselves, or the complex intersections (the meaning) of those vectors? That's a good graph to illustrate the difference between simple 1-degree interface thinking (non-interface thinking, or irrelevant thinking) and interface thinking. Interface thinking involves the relevant meaningful structures which are sufficiently complex to use as tools to see reality clearly.

An interface thought uses interface structures like 'graphs/similarities' as nodes/connections and applies algorithms like 'identify meaning of nodes/connections', so an interface thought would be something like 'this graph standardizes this other graph by abstraction' and then the thought would continue to apply interface analysis until the relevant meanings of the thought had been identified, like 'and this standardization graph has a limit graph like this and interacts with a graph of relevant graphs like this and has these probably relevant optimizations for these intents'. The interface thought applies multiple different workflows and interface structures to calculate meaning as in 'interactivity'.

Interface thinking is the future of thinking.

Not only does interface thinking apply interface structures, it applies them in their 'optimal interactions', optimal interactions like applying 'multiple maximally different workflows/graphs to cover as much variation as possible across interfaces'. Not only does interface thinking apply a different base graph than a standard brain, it applies many different standard base graphs and workflows/queries/connections between these graphs at once.

A good simple metaphor for this is applying a 'graph of graphs' (a meta-graph) rather than a 'graph of nodes', but that is a misleading over-simplification if it leads you to believe that it's just an abstraction layer, or a single application of a graph of graphs.

Interface thinking involves the 'level of complexity' required to see reality clearly; it is the relevant opposite of simple thinking, where simple thinking often produces errors.

A good metaphor for interface thinking is 'scaled thinking' such as 'comprehending a dataset fully by holding the whole dataset in your conscious mind so you can clearly see its relevant connections and differences all at once' instead of 'holding a summary or sample subset of a dataset in your conscious mind at once, as a result of limited conscious ability', but simply applying 'scale' or 'iterations' to generate 'scaled thinking' or 'iteration thinking' is not definitely equivalent to 'interface thinking'; 'interface thinking' requires applying the 'level of complexity' required to see reality, which usually means 'applying optimal interactions between interface structures' like 'applying multiple interface structures like maximally different graphs/connections/interfaces/algorithms for maximum coverage of interface structures'. So merely applying 'scaled thinking' can generate 'simple thoughts' like 'there will probably be a limit to the possible scale of this function' (1-degree interface structures) and 'interface thinking' would 'identify the relevant graphs/algorithms to find that limit'. 'Scaled thinking' is capable of generating relevant complexity, but only in specific cases, like where 'interface analysis' is the structure being scaled.

Most people already apply 1-degree interface thinking, since everyone thinks about limits/structures/standards/perspectives/priorities/variables/intents/etc sometimes.

Most people are capable of 2 or 3-degree interface thinking, if they focus and use tools like visualizations/graphs, but they hit a hard limit on the degree they can achieve, because of their brain's usage patterns, memory capacity, and other limits like energy usage limits. For these people, I'd recommend learning relevant graphs to boost the power of their limited brains, so that even though they're applying very simple 1 - 3 degree interface thinking, they're applying it to relevant interface structures like the 'most relevant graphs identified', which will help them interact with people and computers applying higher degrees of interface thinking. It's not just the degree that is relevant, but other interface structures of thinking, like what the thinking is being applied to (like what graphs the thinking is being applied to).

Outside of small-degree interface thinking is a space where 'graphs/algorithms become default nodes/connections', which enables scaled interface thinking and iterated interface thinking and other variants of interface thinking as 'defaults'. This is the space you want to aim to build in your brain, to upgrade your brain to an interface brain. Once you have an interface brain, you'll find interface thinking possible. It takes practice to build this brain. Aim to spend a few hours per day thinking about interface structures to build an interface brain within a few months to a year. Focus on relevant graphs to speed up this process.

Interface thinking is always evolving, as new relevant structures are identified, and new relevant graphs or optimal queries are identified to replace previous variants.

How can you practice interface thinking, to not only become good at it but also keep up with or stay ahead of computers which will be trained to apply interface analysis?

Practice these types of simpler thought processes:
- what could invalidate/oppose this structure
- what is a graph of these graphs
- what sequence of changes could make this graph irrelevant
- what intents can be skipped, if other intents are implemented
- what are relevant graphs
- what graph would optimize this query

Then you'll be equipped to start trying to have interface thoughts, for which you can practice the following more complex thought processes:
- what graphs are required for a graph sequence that could connect these variables
- what graph optimization sequences could optimize this graph sequence
- what graph generation variables could optimize this emergent graph similarity
- what graph maintains this similarity and also organizes similarities in a new relevant way

Then you can finally start having interface thoughts, like:
- identify an optimal query on this graph of graphs, then identify the meaning of that query given a graph of relevant graphs, then optimize relevant graphs on the graph of graphs for that query
- identify a new way to organize a graph of relevant graphs to optimize workflows for intents like 'identify relevant variation starting from these graphs with these optimizations, optimized for these queries'
- identify a graph of workflows that identifies the optimal workflows to apply iteratively to implement intents like 'identify new relevant graphs to connect relevant variables in a new way or connect new relevant variables'
- identify a graph that optimizes for decisions between relevant alternatives ('similar differences') like low/high dimensional graphs or generative/filtering graphs or base/optimized graphs or connection/node-varying graphs
- identify the graphs that should be applied to implement interface analysis, starting with specific base graphs, applying starting workflows, optimizing for starting metrics/queries, so that all meaningful structures are optimally/trivially identified
- apply interface analysis to identify errors in interface analysis like optimizations with over-prioritization errors on the intersecting interface spectrum graph
- identify workflows to generate interface analysis like 'apply similarities to differences or apply differences to similarities' or 'apply interface graphs of a set of base graphs until the base graphs overlap'

Even more advanced interface thoughts will have graphs as default nodes, like:
- graph this variable subset for identifying similarities, iterate variants of the graph to identify optimal graphs of the variable subset, graph the meaning compared to relevant graphs, graph the relevant variation of the meaning, optimize the graph of the relevant variation for this graph of relevant intents

Interface thoughts are the most complex thoughts that are also relevant/meaningful/interactive. Meaning/relevance/interactivity changes as the base graphs/queries/connections/nodes/interface structures change.

Why complexity? Because complexity can possibly describe reality, and simplicity cannot. Interface analysis at first seems to simplify reality (with interpretations like 'everything is an interface or a limit or a function', etc), but interface analysis is capable of generating new relevant complexity (like 'new relevant graphs to contain new relevant differences'), so reality may be more trivial to describe as a result, but reality also then becomes more complex, the more complex relevant structures are identified.
