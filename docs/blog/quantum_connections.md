# Quantum Connections

It's useful to identify possible variables/functions/structures of quantum connections.


## Structures

'Quantum connections' have default 'connection' structures, like 'clusters/layers/multiple aligned connections/direction/length/directness/position', which enable variables/functions/structures like:
- dependence/coordination/delegation (as in 'enabling info to be identified, then sent on a connection')
- scalability/sequencing/iteration of connections
- synchronization (as in 'holding a variable constant', or 'creating a requirement', which has costs like 'allowing other variables to vary')
- 'multiple aligned connections' impacting different variables (like an 'area')
- changing 'direction of control/starting point/end point/strength/other structural variables' of the connection
- stacking layered/embedded connections on a base connection
- connection patterns like 'alternating/regular connections'


## Optimizations

As a result of the definition of optimality, quantum connections should only be applied when:
- the connection is important/certain/useful/otherwise relevant (as in, it is important that this set of variables is 'held constant', and it is unimportant that other variables are 'allowed to vary')
- the connection pattern is temporary and reversible, sufficient to be minimal in cost/error, or costs/errors are required/optimal for some intent
