# Interface variable interactions

It's useful to identify interactions of an interface variable (like 'time') with other interface variables.

For example, time is related to:
- causality (if a change occurs, something caused the change)
- sequence (time has a sequence)
- ambiguity (if some set of sequences is ambiguous, then time might not be defined to have occurred, while the ambiguity is stable, and increasing ambiguities/uncertainties/reversibilities/relevant variation is a way to increase time)
- randomness (as an opposing variable of time, which can be framed as 'reversing time')
- measurement/standards (time is related to 'relative change, based on a standard/constant/base')
- repetition/cycles (time is related to repeated changes like 'cycles' and 'differences/relevant variation from similarities/constants')
- self-perpetuation/stability (time is related to stability/constants, which enable relevant variation)
- synchronization/similarity (time has specific types such as 'relative time, compared to other types of time')
- irreversibility (time is usually structurable as 'irreversible change')
- problem structures (if the same problems are still relevant problems, time might not be defined to have occurred)

The definition of 'time' in a graph format, as in 'graph time', can be structured as 'relevant variation (like optimizations) of a graph'. A graph can act like a 'clock' by enabling 'indicators of cycles of relevant variation'.

These 'interactions between interface variables' are useful for 'intents related to time', like:
- identifying new/optimal relevant graphs/variation
- synchronizing changes across graphs having some similarity/relevance
- identifying useful graphs of relevant variation (like structures such as spirals)
- increasing potential time/relevance (as in the 'lifetime' or 'possible relevant variation') of a graph
