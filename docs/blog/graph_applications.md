# Graph Applications

It's useful to identify useful applications of a graph, once a relevant graph is identified.


## Applications of specific problem-solving graphs

For example, once a graph that 'solves complexity' is identified (like a graph of 'all useful complexity units/limits/variables', or a graph that 'connects all useful complexity structures to all useful simple structures'), the following are useful applications of that graph:
- iterating/varying the complexity-solving graph to generate new complexity, to identify limits/structures/optimizations of complexity, and otherwise implement intents related to complexity
- applying the complexity-solving graph to 'cover/describe/simplify/reduce other relevant graphs trivially', like applying the complexity-solving graph to optimize the 'graph of the definition of optimality/relevance'
- applying the complexity-solving graph to connect other interface variable extremes (like to 'simplify connections between abstraction/specification')
- specifying the complexity-solving graph until it connects other useful variables


## Applications of generally optimal graphs

Similarly, once a useful graph of the 'definition of relevance' is identified, the following are useful applications of that graph:
- applying the relevance definition graph to generate new relevance, identify units/limits of relevance, and other intents related to relevance
- applying the relevance definition 'regularly' to other graphs, to 'standardize' other variation to relevance


## Optimizations of graphs

Once a graph is defined/identified in a useful way, other graph structures can be identified to optimize that graph:
- identifying optimal graph layers like 'queries of the base graph' can be implemented once the base graph is complete


## Optimization applications

Once a graph is identified/specified/completed/optimized, the graph can be applied as a component/description/other interface structure of other graphs:
- 'applying a complexity-reducing graph as an optimization function of a graph, applied at relevant starting points, in relevant directions of optimization potential'


## Next graphs to identify

The useful 'sequence/structure of these graph applications/optimizations/interactions' is an 'unsolved/incompletely defined problem'.

The target of the 'most optimal graph of relevant graphs' and the 'most useful queries/graph structures/optimizations of that graph, once identified' is a clear general solution structure to identify.

What is still uncertain includes:
- what 'level/interaction/structure of relevant variation' will be implemented in that optimal graph
- what specific implementation of that intent is useful for what optimization metrics, and what optimization metrics are useful (what metrics should the graph implement/optimize for, in order to maximize relevant variation)
- what 'unitary/limit/other structure graph' can most optimally generate/define the optimal graph of relevant graphs
- what graphs should be applied to the optimal graph once it's identified/optimized (should it be varied to generate a possibility space graph, or should it be applied as a component to generate other graphs, or should new defined problems be generated for it to solve)
