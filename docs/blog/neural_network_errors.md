Errors of existing neural algorithms/parameters/functions/networks

	LLMs

		LLMs are biased to be capable of applying the 'variables/change types' gathered from the input training data set, rather than being capable of 'relevant change types' like identifying/generating 'cross-interface changes' or 'relevant new graphs' or applying system optimization interaction rules like 'identifying the level of change/variation required to solve most complex intents like creativity/innovation'. 

		The variables/change types that LLMs are biased toward gathering are simple composable variables as opposed to variables like 'difference from a relevant graph like the similarity index graph', because LLMs don't work to the point of 'identifying relevant graphs', they work to the point of identifying 'common causal components of common sequences'. If a variable isn't fully identifiable in the data set yet, the LLM will struggle to represent it as a simple composable component.

		LLMs are not built to implement intents other than 'identifying common causal components of common sequences', other intents like graph intents like 'optimize a graph' or 'identify relevant graphs' or optimization intents like 'optimize queries for a graph for an optimization metric' (though their functionality can be extended to some degree with 'system prompts' or 'guardrails', if the change types gathered from data support that prompt). However, they can sometimes generate 'approximate functionality' which overlaps with or approximates the functionality of implementing graph intents with 'iteration of degree of composable intents', so that eventually it arrives at simple structures like 'primary components' of relevant concepts/structures like 'interfaces' through applying iterated 'combinations of composable variables'.
		Without 'self-awareness' (like an 'opposition network', or a 'self-copy network for self-evaluation') built-in to the LLM, however, the LLM is unlikely to identify the meaning of 'interfaces' or how to optimally apply them. 
		Without additional functionality like 'identifying interface structures like limits' built-in, the LLM is not likely to gather change types from input training data that allows it to identify anything other than simple structures like 'primary components' of structures, which it would have to iterate quite a bit to generate relevant complex structures like relevant graphs, which it doesn't apply iterations to implement. 
		Without additional cost/error functions like 'different error type cost functions' built-in, the LLM is unlikely to gather relevant feedback like 'cross-interface accuracy' or 'cross-relevant graph efficiency'. 
		Without integration/organization/optimization of change types gathered from training data sets, the LLM is unlikely to generate relevant graphs other than 'simple causal composition graphs' reflecting training data and with errors like 'irrelevant repetition of nodes' and 'overlapping nodes that should be isolated and differentiated in different graphs'.
		LLMs get quite far for some intents by applying 'simple combinations of composable components' which can identify 'simple causal sequences' and 'simple similarities of variables', which given the quality of input training data, is often enough for intents like 'summarize' or 'describe'.
		If LLMs are provided with high relevance data like a 'list of relevant graphs' in a prompt, they can apply the change types they gathered during training to generate simple combinations and can identify simple similarities and simple sequences.
		Iteration of this functionality can overlap with identifying more complex structures, but it will always require iteration, rather than learning semantically what meaning/relevance is and applying relevance by default to avoid applying 'trial and error' to apply every possible irrelevant iteration to eventually identify relevant iterations. An advantage of LLMs is that everything can be represented as a 'causal or combination/iteration sequence of composable components', but a disadvantage of LLMs is that there are many other connection types to generate many other relevant graphs and LLMs don't represent info in 'many different alternate graphs', instead applying one type which requires a relatively high degree of iteration compared to other higher relevance-based methods.

		If LLMs are asked to provide high quality inventions, they don't iterate enough to have the 'independence' or 'definitions/graphs embedded' to understand what that means, and don't have components like 'sufficient memory' or 'organization/compression methods' or 'meaning/intent-identification methods' to identify relevance components like 'newness' or 'independence'.
		Other variable types which might be more useful to identify than 'simple composable variables in sequences' are 'graph sequences/networks' or 'optimized interaction rules' for example.
		An LLMs will be unlikely to generate an 'organized optimized graph of interface structures' like 'interface graphs of graph generation/identification/organization/optimization interaction rules' or the 'graph of relevant graphs', instead arriving at relevant structures by depending on input training data sets to contain change types that can generate relevant connections if iterated enough. 
		Will the LLM apply enough iterations to generate relevant variation? Right now, only if the user provides the correct prompt sequence to do so, giving plenty of examples to filter the solution set of possible meanings of the query, and directly telling the LLM about relevant graphs to apply as 'core components' of its 'change type composition sequences', and if the user directs the LLMs to generate relevance structures with specific related intents, and if the user queries it enough to give the LLM a memory of what relevance/independence is.
		Some functions require more than 'simple combinations/sequences of components' to generate useful outputs like 'relevant complexity'. Because LLMs apply only one connection type ('simple combinations of components'), they will fail to implement complex intents like 'analyze the algorithm/parameters/network/data sets/model to identify graphs that could have generated the same output with fewer queries/variables (or other graphs enabling optimizations)'. Reality is complicated, and 'low degrees of iterations of simple combinations' aren't enough to implement relevant complexity in cases like with 'data sets missing connections' or 'data sets without relevant concepts'. 'Iterated applications of inference/derivation methods using graphs/interfaces/relevance' is required to handle the probable errors like 'interface errors like info errors like missing info' of LLMs. LLMs therefore have over-prioritization errors of 'over-simplification' and 'over-dependence' and 'over-use of identified as opposed to new structures' and other variants of irrelevance.

	Eigenvectors

		Eigenvectors are useful for identifying 'primary change directions', which could theoretically be trivially applied to generate a graph like a 'similarity index graph' (of intersecting/overlapping similarities, indicating embedded similarities of base similarities) if applied with an algorithm to generate that graph. However, eigenvectors applied with a simple 'trial and error' algorithm are unlikely to identify the meaning/relevance of the similarity index graph (the connection like 'embedding' of similarities and the variants of these connections like 'dependency/causality' and 'intersecting spectrum similarities' and so on) and are therefore unlikely to be able to apply the graph optimally, like by mixing it with other relevant graphs to generate more relevant graphs. However, eigenvectors are a good simple method for identifying relevant/prioritized variables when the data allows that (as opposed to deriving meaningful variables from low info).

	Gradients

		Gradients reflect a 'change in parameters' generated by an update function which guesses the 'next best parameter update to try' after the previous/initial failed update. This is a local, low-info learning structure which doesn't apply meaning analysis, like 'common good guesses' or 'common good guess update patterns' or 'maximally different function patterns to identify good guesses across functions'. However, gradients are useful for indicating 'directions of change' and 'patterns of change' and 'types of change'.
