# Interface Analysis Iterations

It's useful to identify the 'number of iterations' of interface analysis to apply.


## Interface Analysis Iteration Variants

1. Applying a 'constant number of iterations' of interface analysis is suboptimal for obvious reasons, as this constant will not reflect 'required variation of different cases'.

2. Applying a number of iterations 'until some relevant structure emerges' has the following relevant variants:
- apply iterations until the graph is too complicated to analyze trivially/otherwise relevantly (then subtract an iteration)
- apply iterations until the 'structures (like concepts) that are useful to analyze the graph' stop changing
- apply iterations until some other graph emerges that is more useful (until some layer emerges as more useful to identify, or until some other new core structure emerges as the more useful interface to apply)
- apply iterations until the graph is graphable on some 'meta-graph' as a point/node because the value/relevance of the graph is understandable/graphable at that point
- apply iterations until the graph becomes similar to some known relevant graph

3. Applying a 'relevant variant of a constant' is another alternative:
- apply a 'commonly relevant' number of iterations
- apply an 'average of relevant' number of iterations
- apply a 'variant of a constant' number of iterations that reflects 'relative complexity of the case, compared to the common number of iterations'


## Other variants of 'iteration number' (of applications of interface analysis)

Other interface structures are useful to identify than 'iteration number' of 'interface analysis applications':
- 'types/variations/structures' of 'interface analysis organizations/implementations/specifications/simplifications/connections/optimizations'

Specifically, the following variants are particularly relevant:
- optimal organizations/graphs of interactions of interface analysis
- optimal combinations/structures of interface analysis for multiple/otherwise relevant intents
