# Concept errors

Conceptual errors are the most important errors to identify, because concepts are often the most useful interface for solving problems, by thinking through the conceptual interactions first before applying the concepts.

So identifying conceptual errors first will help optimize applications of conceptual interactions.


## Core concept errors

Error structures like 'missing/overlapping/extreme' applied to concepts generate core error structures of concepts.

Missing concepts, overlapping concepts, poorly defined concepts like 'extremely abstract/specific concepts', and meaningless concepts like 'extremely variable concepts' are all examples of core error structures of concepts.


## Concept interaction errors

Errors in conceptual interactions generate other concept errors, like:
- whether the interactions of a concept were 'applied to their conclusion/limit/optimization/structure' so as to be correctly/completely/relevantly identified
- whether a concept was 'applied/implemented/integrated/iterated to its maximum relevance'
- whether a 'concept interactions with other concepts' has errors, like applying 'the concept definition network of balance to the concept definition network of power', which can be incompletely/otherwise incorrectly applied
- whether a concept was applied/implemented/defined with the correct/relevant structure/function/interface


## Concept graph errors

Errors in concept graphs are another structure of concept errors:
- incorrectly applying a concept as a priority/component/layer/generative variable/other interface structure of a graph
- incorrectly connecting/differentiating concepts in a concept graph


## Concept function errors

Concepts can be incorrectly optimized/integrated/applied/otherwise processed with functions:
- incorrectly optimizing for one concept over the correct concept
- incorrectly optimizing a concept definition/interaction/other interface structure
