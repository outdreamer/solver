# AI Optimization Intent Structures

It's useful to identify useful structures like 'sequences/networks' of AI optimization intents.


## Examples

For example, it's useful to implement the following intent sequence:
- identify a sufficiently complete set of independent important variables (like 'interface variables') required to explain/predict/identify/generate/optimize a 'sufficiently high ratio of relevant variation', which can be applied as a 'unit of relevance', thereby 'identifying that the algorithm has sufficient information to optimize for more optimal metrics/intents' (which is related to 'identifying connections, then identifying clusters, then identifying more optimal clusters, then identifying optimal cluster layers/generators and cluster limits/errors, etc' in a graph to 'continue switching to more useful higher variation structures')
- identify what is 'possible/otherwise relevant to identify/generate' with that set of variables
- identify useful intents to implement with that set of variables, related to graphs (like 'identifying the relevant graphs of interface variables' or 'identify the most important graph structures to identify causes of, in a causal graph, like cross-graph layer slices')
- identify useful graphs of these intents (like 'graphs of optimal positions of problems/intents to solve in an optimal sequence' and 'graphs of optimal sequences like where solving one problem linearizes the remaining problems in the sequence')
- identify optimizations to the useful graph of these intents

But it's more useful to implement the following intent sequence:
- identify useful graphs, graph optimizations, and useful graph problems to solve that would invalidate other problems
- solve (as in 'identify a causal graph related to') the identified useful intents to solve in the graph problem space
- optimize the graph of solved problems/intents to 'generate/standardize/integrate new relevant variation'


## Relevant Graphs

So an 'optimal learning algorithm' like 'recursive self-optimization algorithms' would identify at some point that there is a 'more useful intent sequence to implement' and 'switch to that sequence', answering the question of 'what is optimal to learn' (like 'important variables', and 'interactions of those important variables', and 'optimizations of those interactions for the next optimization metrics').

This implies the usefulness of a 'flexible graph that identifies the most optimal intents to solve with current information and adapts current processes to newly derived optimal intents', which is the goal of recursive self-optimization (identifying this graph that manages/optimizes intent interactions to switch to more optimal intents in an optimal way).

Other relevant unsolved graphs include:
- the graphs that 'define the graph problem space' sufficiently to 'trivialize the remaining unsolved intents' (like 'trivializing the remaining unsolved problems' to an 'ambiguity resolution' problem, as in 'requiring new info')
- identifying a predict/review algorithm that 'reviews/identifies more optimal paths that could have been taken to current optimal points' and 'predicting optimal paths to the next optimal points', integrating these algorithms like by 'integrating more optimal previous paths to optimize predicted next paths', which applies these 'opposing functions as an alternating wave'
- identifying a useful graph of optimal states of any structure, like a 'graph that connects optimal states of any structure in a wave/spiral'


## Priorities

Recursive self-optimization priorities include:
- identifying the correct 'definition of optimality', before it's scaled/applied iteratively (or identifying its possible errors, and opposing them when applying the definition)
- identifying optimal intents (or identifying alternative structures like identifying 'optimal intent-identification algorithms'), before 'switching intents' is required (as in 'before current intent implementations cost too much')
- identifying useful graphs to 'organize/optimize info that is learned'
- identifying useful graphs to 'identify what is optimal to learn/derive' ('learning' being related to 'identifying casual graphs in high info problem spaces', 'deriving' being related to 'identifying useful implications/extensions/intents of learned info', which is a useful 'opposing function set', similar to 'filter/generate' and 'predict/review')
- identify how frequently newly identified variation should be 'extending/specifying/optimizing the graph of optimality'
